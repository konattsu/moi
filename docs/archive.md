# archive の配置と管理

archive は一つの配布物から宣言された内容を取り出し、配置して維持する。定義のキーは [TOML リファレンス](toml-reference.md#kind--archive)、共通の条件・検証・実行順は [実行モデル](execution.md) に従う。

## 宣言と適用条件

url・sha256・format・root・dst・policy・version などは全て一つの `[[operations]]` に直接書く。適用条件は when だけで表す。architecture 共通なら when.arch を省略し、CPU 別の配布物だけ when.arch が排他的な別操作に分ける。

root は archive 内で取り出す基点のディレクトリ。include はその基点から通常ファイルを選ぶ任意の非空配列とする。

| 宣言 | 配置する内容 | 管理範囲 |
| --- | --- | --- |
| include 省略 | root の全内容 | dst 自身とその配下全体。専用ディレクトリが必要 |
| include 指定 | 列挙した通常ファイル | dst 配下の選択ファイルだけ。dst と親ディレクトリは共有できる |

include は root からの相対パスの完全一致とし、元の相対位置を保って dst へ配置する。glob・除外指定・リネーム・内容加工は扱わない。ディレクトリ、symlink、root 自身を include の項目には指定できない。絶対パス・.. を拒否し、正規化後の重複や、一方のファイルが他方の親になる指定も拒否する。指定したファイルが配布物に存在しなければ、変更前にエラーにする。

例えばフォントは、必要な4書体を利用先へ直接配置できる。

```toml
[[operations]]
kind = "archive"
when = { distro = ["arch"] }
dst = "~/.local/share/fonts/udev-gothic"
policy = "pinned"
version = "2.2.0"
url = "https://github.com/yuru7/udev-gothic/releases/download/v2.2.0/UDEVGothic_NF_v2.2.0.zip"
sha256 = "45faeef7b5d8bc591bcc5887a2ca0c5fb9028066f18a5a52cd6f10b7d655ba37"
format = "zip"
root = "UDEVGothic_NF_v2.2.0"
include = [
    "UDEVGothic35NF-Regular.ttf",
    "UDEVGothic35NF-Bold.ttf",
    "UDEVGothic35NF-Italic.ttf",
    "UDEVGothic35NF-BoldItalic.ttf",
]
```

この例では include に列挙した4書体だけを配置する。

周辺ファイルを含む構成が必要な場合は、include を省略して全体を専用ディレクトリへ配置する。起動リンクは symlink 操作、font cache などの後処理は shell 操作で管理する。

## 管理対象と配置先の競合

操作の適用条件を評価した後、実際に管理する対象を求める。

- 全体配置：正規化した dst とその配下全体。
- 選択配置：各 include の相対パスを正規化した dst に結合した、最終配置の通常ファイル。

HOME 展開・区切り・. 要素・末尾の / の正規化は実行モデルに従う。管理対象自身と親の symlink は許可しない。選択配置で必要な親ディレクトリは作成できるが、archive の所有範囲には含めず、再帰的に削除・置換しない。

同じ dst の選択配置は、最終配置ファイルが重ならなければ共存できる。排他的な when の操作も同じ対象を宣言できる。全体配置の範囲内への別操作、同じファイルへの選択配置と file / block / symlink の併用、ファイルを親とする別の配置は競合として変更前に拒否する。

## 管理記録の保存先と単位

管理記録は全体配置なら専用ディレクトリごと、選択配置なら最終配置ファイルごとに、一つの UTF-8 JSON ファイルとして保存する。module 名や environment 名は識別に使わない。

```text
~/.local/state/moi/archives/<管理対象パスのSHA-256>.json
```

ファイル名は、正規化した管理対象の絶対パス文字列の UTF-8 バイト列を SHA-256 にかけた、小文字16進数64桁。末尾に改行や NUL は加えない。これは配布物や配置ファイルの内容のハッシュではない。

選択配置では dst が同じでも管理対象が異なれば記録は衝突しない。選択ファイルを増減しても、残る対象の記録のパスは変わらない。

記録内にも管理対象の絶対パスと操作の dst を保持し、要求した対象と一致することを確認する。記録形式には版を付け、初版を 1 とする。破損や未対応の版はエラーにする。

## 記録する情報

| 区分 | 保存する情報 |
| --- | --- |
| 共通 | 記録形式の版、管理対象の絶対パス、操作の dst、全体／選択配置の区別、policy、導入した version、sha256・format・root、正規化した include の集合（省略時は全体配置）、選択配置ではそのファイルの root からの相対パス |
| pinned・全体配置 | 専用ディレクトリ自身を含む全管理パスの一覧・種類。通常ファイルは内容の SHA-256 と権限、ディレクトリは権限、symlink はリンク先 |
| pinned・選択配置 | その通常ファイルの内容の SHA-256 と権限。共有の dst 全体の一覧・権限は記録しない |
| preserve | 現在の required_paths の導入時の種類・必要な実行権限。内容のハッシュやその他のファイルの一覧は保存しない。選択配置では各ファイルの記録に、そのファイルが必須かと、必須の場合の検証情報を保持する |

共通情報は最後に導入成功した定義を示し、現在のアプリの版ではない。self-update 後も自動で書き換えず、version の問い合わせや出力解析は行わない。再導入成功時に新しい定義の記録へ置き換える。

記録だけを失った既存ファイルについて、自動で記録を再生成して引き取ることはしない。include から外したファイルとその記録は自動削除せず、以後の適用対象から外す。宣言から消した対象の削除は利用者が判断する。

## 定義変更と再導入

今回適用する操作の policy・version・sha256・format・root・全体／選択配置・正規化した include 集合を、管理記録と比較する。一つでも異なれば pinned / preserve ともに現在の宣言から再導入する。include の順序は一致判定に影響しない。

選択配置では、現在選択する全ファイルの記録を確認する。一つでも再導入が必要なら、操作単位で取得・検証し、現在選択するファイルを再配置してそれぞれの記録を更新する。選択から外れたファイルは触らない。

version は最低版の指定ではなく、文字列の一致だけを比較する。1.0 と 1.0.0 も異なる値とし、アプリの実体の版は取得・比較しない。URL だけの変更、note、操作の配列位置、module 名、今回適用しない操作の編集は再導入の理由にしない。digest は16進数の大小文字を区別せず、パスは正規化して比較する。

記録の破損や配置先の種類の不一致などの判定エラーは、定義が変わった場合も上書きで解決しない。

## policy ごとの状態判定

定義が一致する場合、次の範囲で実際の配置を照合する。充足なら unchanged とし、取得・解凍・再配置を行わない。

| policy と配置 | 充足条件 |
| --- | --- |
| pinned・全体配置 | 専用ディレクトリ全体の内容・種類・権限・リンク先・パスの一覧が記録と一致。余分なファイルも差分 |
| pinned・選択配置 | 選択した通常ファイルの内容と権限が記録と一致。dst 内の他のファイルは検査・変更しない |
| preserve | required_paths の存在・種類・必要な実行権限を満たす。必須パス自身を含む内容変更と、必須でない選択ファイルの内容変更・欠落は許容 |

pinned は通常の差分があれば現在の宣言から再配置する。self-update も差分となる。全体配置で余分なファイルがなくなるのは、専用ディレクトリ全体を差し替えるためである。選択配置で、他のコマンドなどを余分なファイルとして削除することはない。

preserve の required_paths は dst 内を指す相対パスの非空配列であり、pinned には指定しない。全体配置では導入時に種類と必要な実行・探索権限を記録する。必須パスが symlink なら配置先内で解決できる参照先の存在・種類・必要な実行権限も確認し、リンク先文字列や内容の一致は要求しない。

選択配置の required_paths は正規化後に include の部分集合とし、選択した通常ファイルだけを必須にできる。必須でない選択ファイルの内容変更や欠落だけでは再導入しない。有効な記録に現在の必須パスの検証情報がなければ、再導入して情報を確立する。

| 管理記録の版 | 実際のアプリ | 現在の定義と状態 | preserve の結果 |
| --- | --- | --- | --- |
| 1.0 | self-update 済みの 1.3 | 同じ定義で必須パス充足 | 1.3 を保持。記録は 1.0 のまま |
| 1.0 | 1.0 | version を 1.1 に変更 | 1.1 を導入し記録も更新 |
| 1.0 | self-update 済みの 1.3 | version を 1.1 に変更 | 1.1 を導入。downgrade を許容 |
| 1.0 | self-update 済み | 同じ定義だが必須パス欠落 | 修復のため 1.0 を再導入 |

実際のアプリの版は表の説明用。定義変更・修復時の downgrade 防止や最低版以上の保証は行わない。どちらの policy もアプリの起動成功そのものは保証しない。

## 記録と配置の組み合わせ

以下は管理対象ごとの規則。選択配置では現在の全選択ファイルについて確認する。

| 状態 | 処理 |
| --- | --- |
| 記録も対象もない | 初回導入が必要 |
| 有効な記録と対象がある | 定義と policy に従って照合 |
| 有効な記録があり対象がない | 定義変更時、pinned、または必須パスなら再導入。同じ定義の preserve の必須でない選択ファイルなら欠落を許容 |
| 対象があるが記録がない | エラー。既存配置を引き取らず上書きしない |
| 記録の破損、未対応の版、対象パスの不一致 | 対象の有無にかかわらずエラー |

全体配置の専用 dst 自身がなければ再導入する。読み取り失敗などの判定エラーは未充足として扱わない。選択配置の基点となる共有 dst が既に存在することは、管理対象の無断引き取りには当たらない。

## 導入と再配置の手順

1. 配布物を取得して checksum を検証し、一時領域で展開・内容検証する。絶対パス、..、展開先を逸脱するリンク、特殊ファイルを拒否する。全体配置では安全な内部リンクを許可する。
2. include 省略なら root 全体、指定時は列挙した通常ファイルだけを配置候補にまとめる。選択外のファイルは最終配置へ持ち込まない。root・include・required_paths の検証が全て終わるまで既存配置を変更しない。
3. 各管理対象と同じファイルシステム上に新しい配置を用意する。全体配置はディレクトリ、選択配置は各ファイルを扱う。既存の管理対象があれば一意な退避先へ移す。共有 dst 全体は退避しない。
4. 候補を最終配置へ移し、今回の policy が要求する状態を確認する。選択配置では必要な親だけを作成し、既存の別ファイルや共有ディレクトリの権限は変更しない。
5. 各対象の新しい管理記録を、記録先と同じディレクトリの一時ファイルへ完全に書き、対応する JSON を rename で置き換える。配置成功前に記録だけを更新しない。
6. 操作内の配置確認と全記録の保存まで成功したら、その実行で退避した旧対象を削除する。

全体配置は専用ディレクトリ全体の差し替え、選択配置は指定したファイルだけの差し替えである。選択配置を共有ディレクトリ全体の置換として実装してはならない。管理記録がない既存対象や、宣言と種類が異なる対象は上書きしない。退避物の削除も今回扱った対象に限定する。

## 失敗・中断時の扱い

失敗で後続を止める。記録は正常導入の状態照合用であり、中断復旧用の処理履歴は作らない。配置と記録をまとめた原子性、複数ファイルの原子性、自動復旧、原状回復、中断の完全検出は保証しない。

配置後・記録保存前の中断では、新配置と旧記録、または記録のない新配置が残り得る。選択配置では一部ファイルだけが更新される場合もある。全記録保存後・旧対象削除前なら新配置・新記録と退避物が残り得る。

失敗時は管理対象・記録・今回の一時領域と退避先を診断に示し、退避した旧対象を失敗処理で消さない。次回は通常の記録と配置で判断し、退避物を自動探索して復旧・削除しない。判断できない状態は利用者が確認・退避・整理して再実行する。

plan は定義から管理範囲を求め、管理記録と確認可能な配置を照合する。取得・展開・記録作成・再配置・退避物の整理は行わない。同時 apply は [実行モデル](execution.md#plannote同時実行) と同じく非対応とする。
