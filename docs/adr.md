# 設計判断

## 001: 状態と独自処理を分ける

**決定:** 標準操作が状態判定と変更を所有し、適用条件・充足・未充足・判定エラーを区別する。独自処理は shell の check / run に残す。

**理由:** script 内部の副作用を解析せずに、標準操作の状態収束と plan の意味を揃えられる。

**帰結:** operations は記述順とし、操作の ID や依存グラフ、汎用 unless、判定無視の force は設けない。shell の成功を変更件数に含めない。

## 002: 定義全体と今回の適用範囲を分けて検証する

**決定:** 指定 environment の全 module を parse し、型・書式・依存先・循環を検証する。入力の存在、配置先の状態と競合は、選択され今回の when に一致する操作を対象とする。

**理由:** environment 全体の定義の整合性を保ちながら、今回使わない入力や配置先は要求せずに済む。

**帰結:** 未選択 module の定義不備でも停止する。他の environment は検証しない。依存先を推移的に選び、利用側を逆向きには選ばない。環境条件で排他的な操作は同じ配置先を宣言できる。

## 003: 提供側 module が PATH を解決する

**決定:** 起動時の環境を継承し、静的な PATH は path_prepend、導入後に解決する PATH は path_export で提供側 module に定義する。全操作の成功後に取得した値を後続全体へ渡す。

**理由:** 導入したコマンドの利用に必要な PATH を提供側で解決することで、利用側にツール固有の初期化処理を重複させずに済む。

**帰結:** コマンドの有無によるフォールバックはしない。path_export があれば導入済みでも毎回取得し、静的な PATH だけで足りる定義では省略する。非対話・非ログインの shell を使い、BASH_ENV や起動元の Bash 関数を引き継がない。取得した PATH は後続の子プロセスに設定する。

## 004: 対象ユーザーと package 導入の責務を固定する

**決定:** moi は対象ユーザーとして動き、system package の操作だけ必要に応じて昇格する。packages は選択 module から集約し、全 module 操作より先に導入する。

**理由:** HOME・設定ファイル・管理記録を実行ユーザーに揃え、system package の管理を package manager に任せられる。

**帰結:** sudo 元のユーザーは推測しない。追加リポジトリが必要なものは登録から導入まで shell に書く。depends_on によって package 導入のタイミングは変わらない。独自処理の sudo は定義側が明記する。

## 005: 静的入力と直接の配置先を使う

**決定:** file / block の src は module 基準の相対パスで取得した repository 内の静的ファイルに限定する。共有入力への symlink は repository 内で解決できる場合に許可し、標準操作の配置先の親に symlink を許可しない。

**理由:** 入力を変更前に確認でき、配置先の別表記や親リンクの切り替えによる管理対象の変化を避けられる。

**帰結:** 生成から配置までの処理は shell にまとめる。親がリンクなら実際の配置先を直接指定する。入力側の共有 module の symlink、リンク自身を管理する symlink 操作、archive 内の安全なリンクは別の規則として扱う。

## 006: archive が配置する内容と管理範囲を宣言する

**決定:** archive の全項目を operations に直接書き、条件は when に統一する。include 省略時は root 全体を専用 dst へ配置し、指定時は列挙した通常ファイルだけを dst 配下の同じ相対位置へ配置する。全体配置はディレクトリ、選択配置は各ファイルの絶対パスで識別・記録する。

**理由:** 配置する内容と管理範囲を一致させ、共有ディレクトリの他のファイルへの影響を避けられる。周辺ファイルを含む構成が必要な場合は、専用ディレクトリへの全体配置を使える。

**帰結:** ファイル選択は完全一致に限り、任意の削除・加工・フックへ広げない。pinned は管理範囲だけを照合し、preserve は required_paths を確認する。選択配置の required_paths は include の部分集合にする。version・配布物・include・policy の変更時は再導入し、downgrade を許容する。include から外れたファイルや記録は自動削除せず、共有 dst は置換しない。配置と全記録の保存成功後に旧対象を削除する。詳細は [archive の配置と管理](archive.md) に集約する。

## 007: 中断復旧と並行 apply を管理しない

**決定:** 通常の管理記録に基づく状態収束は行うが、配置切り替えの中断に対する復旧用記録・自動復旧・原状回復の保証は設けない。同一ユーザーの同時 apply は非対応とし、ロックによる検出も行わない。

**理由:** 個人環境の逐次適用を対象とし、処理段階の永続化や複数の実行を調整する仕組みは持たない。

**帰結:** 失敗時は停止し、それまでの変更を保持する。判断できない中断状態は利用者が退避・整理して再実行する。正常導入の管理記録は残す。

## 008: plan と note に実行履歴を持ち込まない

**決定:** plan は shell や package manager を実行せず、確定できない状態を実行時に判定すると表示する。note は --show-note 指定時だけ表示する。

**理由:** 任意 shell の副作用を事前に保証できず、案内の表示のためだけに初回判定や履歴を管理する必要もない。

**帰結:** apply は直前の観測結果を使い、plan を固定済みの実行計画にしない。note は処理を実行せず、初回・通常時とも既定では表示しない。
